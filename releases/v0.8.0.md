# v0.8.0 — large uploads

> **The admin panel accepts images up to 20 MB and PDFs up to 50 MB, sent directly from the browser to Vercel Blob.** **6 commits** since v0.7.1. No migrations. The demo contact email also changes.

This release lifts the upload size limit of the panel. The browser sends the file to the store, and the server checks and converts it afterwards.

---

# Uploads
- Images can be up to 20 MB and PDFs up to 50 MB. The browser sends the file straight to Vercel Blob.
- The flow has three steps. The route `POST /api/admin/upload` issues an upload token. The browser uploads the file to the `tmp/` folder. Then `finalizeMediaAction` checks the real size and type of the stored file.
- An image is re-encoded to WebP. A PDF is copied under a random name. The temporary file is deleted in both cases.
- The browser refuses a file over the limit before it sends it. The server and the store check the limit again.
- The Content Security Policy gains two `connect-src` origins: `https://*.public.blob.vercel-storage.com` and `https://vercel.com/api/blob/`.
- The live demo keeps uploads off because demo mode is read-only.

# Demo
- The demo contact email is `info@tanyeri-lighting.vercel.app`. It reaches a deployment only through the demo seed, so run `pnpm db:seed:demo` to apply it.

# Checked by hand
The upload flow was checked against a real development store:
- A 19.5 MB JPEG was stored as a 1.4 MB WebP with no EXIF data.
- A 49.5 MB PDF was stored with the right size and opened in the public viewer in a production build.
- A 21 MB image and a 51 MB PDF were refused in the browser. With the browser check bypassed, the server and the store refused them.
- Mislabelled files were refused.
- The `tmp/` folder was empty after a successful upload and after the refusals.
- A signed-out request returned 401, a path outside `tmp/` returned 400 and demo mode returned 403.
- No Content Security Policy violation appeared.

# Known limits
- A file stays in `tmp/` if the browser closes between the upload and the finalize step. There is no automatic cleanup.
- The public PDF viewer downloads the whole file. A 50 MB catalog costs about 50 MB of transfer per view, against the 10 GB Hobby quota.
- The public catalog viewer does not open files under `next dev` and shows its download fallback, including for the demo PDFs. Production builds work. The cause is not yet known.
