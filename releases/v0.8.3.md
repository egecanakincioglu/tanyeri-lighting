# v0.8.3 — security review fixes

> **A security review of the whole project found no serious flaw, and this release closes the smaller gaps it did find.** **15 commits** since v0.8.2. No migrations.

The review is recorded in [`docs/security/review-2026-11.md`](../docs/security/review-2026-11.md). It found no write that a signed-out visitor or the demo account can reach. It found no XSS, open redirect, SQL injection or upload path bypass.

---

# Security fixes
- Changing the e-mail address now asks for the current password. Each account gets 5 wrong tries per 15 minutes.
- Demo sessions last 1 hour. Each successful sign-in deletes expired sessions.
- Password reset tokens are stored hashed.
- The demo contact form skips the rate limits, so nobody can use up its daily ceiling.
- On Vercel, the app refuses placeholder values copied from `.env.example`.
- Geolocation headers are read only on Vercel.
- All paths send `X-Frame-Options: DENY`. The `X-Powered-By` header is gone.
- The stale 5 MB Server Action body limit is removed.
- The message id is validated before the query that marks a message as read.
- If revoking other sessions fails after a password change, the message now says that other devices may stay signed in.

# Dependencies
- Patched copies of `glob` and `minimatch` are used in development tools.
- `pnpm audit --prod` is clean.
- One moderate advisory remains on `minimatch` 3.1.5 under the lint plugins. It affects development only, and no safe fix exists yet. The review document records it.

# Docs
- A release and rollback runbook was added.
- The README shows screenshots of the site and the panel.
- The roadmap and ADR 0007 were corrected.

## Technical notes

- Migrations: none.
- No new environment variable. `.env.example` is unchanged.
- Existing password reset links stop working after the upgrade, because tokens are now stored hashed.
- Signed-in demo sessions follow the new 1-hour limit for new sign-ins.
