# v0.8.2 — metadata in the head

> **Page title and description now stay in the head of every page, for every client.** **2 commits** since v0.8.1. No migrations.

This release turns off metadata streaming. A cold render on the live site could put the description in the body instead of the head.

---

# Metadata in the head
- On the live site, a cold render could send the description in the body. Crawlers that do not run scripts and the Lighthouse description audit do not look there.
- A Lighthouse description audit on a product page failed on 3 of 4 desktop runs because of this.
- `next.config.ts` now sets `htmlLimitedBots: /.*/`. Every client gets the title and description in the head, and the page waits for its metadata before the head is sent.
- A request with no browser identification string still streams. This is not covered by the setting.
- A test checks the setting. The architecture page describes it in the SEO section.

# Local check
- With a fresh `next start` for each sample and the first request to a product page, the description and title were before the end of the head in 0 of 6 samples with a Chrome browser identification string and 1 of 6 with a crawler identification string before the change. After it, 6 of 6 for both.
- In headless Chrome, 4 loads after the change had the description in the head every time, with no console errors.
- Time to first byte stayed between about 225 and 365 ms in both sets locally. A real cold function with a slow database was not measured.
- The effect on the deployed site was not measured at the time of writing. No scores or search results are claimed.
