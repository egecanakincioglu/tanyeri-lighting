# v0.8.1 — search indexing

> **The live site is open to search engines, and the public catalog viewer opens under `next dev`.** **2 commits** since v0.8.0. No migrations.

This release records the decision to open the live site to search engines before 1.0.0. It also fixes the catalog viewer in development.

---

# Search indexing
- The live site is open to search engines. `SITE_INDEXING=on` is set for the Production environment only.
- Preview deployments stay `noindex`.
- The default in `.env.example` stays `off`, so local runs and fresh installs stay closed unless the value is changed.
- The README, the architecture page, the development setup guide, the release guide, the roadmap and ADR 0011 now say this. ADR 0011 keeps the earlier rule visible and records the change with a note dated 2026-11-04.
- The setting takes effect with the next production deployment, which is this release. Indexing takes time. No search results have been measured yet.

# Catalog viewer
- The public catalog viewer now opens under `next dev`. It no longer falls back to the download link.
- Cause: in `PdfPage`, the effect awaited `pdf.getPage()` before it assigned the render task. A Strict Mode cleanup during that wait could not cancel the first pass, so two renders shared one canvas.
- This closes the known limit listed in the v0.8.0 notes. Production builds were not affected.

---

## Technical notes

- Migrations: none.
- No new environment variable. `.env.example` is unchanged.
- `SITE_INDEXING=on` is a setting of the Production environment in Vercel, not a file in the repository.
