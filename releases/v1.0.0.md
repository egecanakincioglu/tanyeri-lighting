# v1.0.0 — first full release

> **Tanyeri Lighting is a bilingual website and admin panel for a fictional lighting brand, and this is its first full release.** **1 commit** since v0.8.3. No migrations.

The project is a public portfolio project. The code is source-available under the [PolyForm Noncommercial License 1.0.0](../LICENSE). A live read-only demo runs at https://tanyeri-lighting.vercel.app.

---

# Public site
- Every page exists in Turkish and English. Each address has a language prefix (`/tr`, `/en`), and page paths are localized, for example `/tr/urunler` and `/en/products`.
- Pages: home, about, vision, services, products (category tabs, pagination and a product page), catalogs with a page-flip viewer, projects with a before and after slider, references, blog, contact form, privacy, terms and a not-found page.
- Search and sharing: localized titles and descriptions, canonical addresses with language alternates, a sitemap, `robots.txt`, a plain-text site guide and structured data.
- The contact form stores messages without an IP address and is protected by a honeypot field and a rate limit.

# Admin panel
- Content management for the home banner, featured products, promo boards, work areas, company settings, social links, about and vision, references, services, projects, blog articles, products, categories, catalogs and legal pages. All texts are stored in both languages.
- Contact messages can be read and deleted.
- Page information for search can be edited for each page.
- Visit statistics show visits, page views and countries. Addresses are shortened before they are stored.
- The account screen changes the email address and the password. Password reset works by email when SMTP is set, or by the `pnpm admin:reset-password` command.

# Demo mode
- The live site runs in demo mode. Saves are refused, contact messages are not stored and a notice band shows on every public page.
- The demo panel is at https://tanyeri-lighting.vercel.app/tr/yonetim/giris. The sign-in details are in the [README](../README.md#live-demo). The account is read-only and public on purpose, and it works only while demo mode is on.
- `pnpm db:seed:demo` fills a local copy with fictional demo content.

# Security
- A security review covered authorization, uploads, output, public forms, redirects and input, sessions and cookies, visit statistics, and the seed and reset command. It found no write reachable when signed out or with the demo account, and no XSS, open redirect, SQL injection or upload path bypass. The smaller items it found were fixed in v0.8.3.
- The review is recorded in [`docs/security/review-2026-11.md`](../docs/security/review-2026-11.md).
- The site sends a nonce-based Content Security Policy and security headers. There is no public sign-up. An authorization check in every admin page, action and handler is enforced by a static check in CI.

# Quality
- Every pull request must pass 12 required checks: `policy`, `pr-text`, `tooling (linux)`, `tooling (windows)`, `quality`, `semgrep-registry`, `zizmor`, `test`, `build`, and three `site-audit` jobs (pages, mobile and desktop).
- The site audit runs against a production build. The Lighthouse gate is 90 in all four categories on mobile and on desktop, with 95 and above expected ([ADR 0010](../docs/adr/0010-quality-thresholds.md)). Pages between 90 and 94 pass with a warning.
- The audit also requires zero axe violations, zero horizontal overflow, zero target size violations and zero console errors at every width of the device set ([ADR 0009](../docs/adr/0009-quality-targets.md)).
- `src/server` and `src/lib` keep at least 80% line coverage.

# Run it locally
