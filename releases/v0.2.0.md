# v0.2.0 — Server foundation

> **The server side of Tanyeri: authentication, file storage, contact messages and the content schemas.** **81 commits** since v0.1.0. 7 migrations. **Visitors see no change:** the site still shows the placeholder page and stays out of search indexes until 1.0.0. From this version the project is under PolyForm Noncommercial 1.0.0.

This release builds the back end that the public pages will use. It adds sign-in for administrators, a shared authorization check, protected file uploads, a contact form action and the database tables and services for all site content. No page uses them yet.

# Authentication
- Better Auth core with email and password sign-in and database sessions.
- There is no public sign-up. Administrator accounts are created on the server.
- Explicit rate limits, stored in the database: sign-in 3 requests per 10 seconds, password reset request 3 per 60 seconds, password reset 5 per 60 seconds.
- The first administrator is created with `pnpm db:seed`.
- A lost password is recovered with `pnpm admin:reset-password`.

# Authorization
- One shared session guard protects admin pages, Server Actions and route handlers.
- A static check (`tooling/scripts/check-admin-guard.ts`) runs in the `policy` job and fails CI when a guard is missing.

# Demo mode
- A write guard refuses every change to data while demo mode is on.
- State-changing account endpoints (password change, email change, password reset and others) are refused with 403. Sign-in and sign-out stay open.
- The contact form does not store messages in demo mode; it returns a summary to the sender.

# Rate limiting for public forms
- Public forms count requests per visitor in the database.
- The counter key is an HMAC of the address. The plain IP address is never stored.
- IPv6 addresses are grouped by their /64 prefix, so one network counts as one visitor.

# File storage
- Uploads go to Vercel Blob through a single upload pipeline.
- The pipeline refuses files over 4 MB, detects the file type from the content, and re-encodes images to WebP (longest side 2048 px) so metadata such as EXIF and GPS is dropped. PDF files are accepted as well.
- Without `BLOB_READ_WRITE_TOKEN`, storage stays off.

# Email
- SMTP is optional. When it is not configured, the site works without email.
- With SMTP set, administrators can reset a password by email. The email is sent after the response, so known and unknown addresses get the same answer.

# Contact messages
- The contact form action validates the input, has a honeypot field, applies the rate limit and stores the message.
- Message services list stored messages, mark them as read and delete them. No public page uses them yet.

# Content
- New tables and services for site settings, page metadata, legal pages, categories, products, catalogs, home page blocks (banner, promo boards, featured products, application areas), service cards, the about page, projects and references.
- Products keep their old slugs as redirects when a slug changes.
- Bilingual fields use one required column per language, and a page never falls back to the other language.
- A limited Markdown renderer renders stored text without raw HTML. It supports only a small set of elements.

# Quality
- CodeQL is replaced by the Semgrep registry rules and zizmor, because the CodeQL terms allow free use only on OSI-licensed code (ADR 0012). The number of required checks is 12.
- GitHub Actions workflows are hardened: no credentials are kept after checkout, and caching is off in the release job.
