# v0.1.0 — Foundation: skeleton, quality gates and release pipeline

> **The first Tanyeri release: the foundation of the rewritten application.** **150 commits** since the first commit, pull requests #1–#51. No migrations (the database tables arrive in phase 4). Live at https://tanyeri-lighting.vercel.app — kept out of search indexes until 1.0.0.

There is nothing for visitors to see yet; the page says "Site hazırlanıyor." This release brings the application skeleton every later feature builds on, the database layer, the quality gates that check every pull request, and the path to production.

---

# Application
- New Next.js 16 (App Router) and React 19 skeleton; no files were carried over from the old code.
- Two languages, Turkish and English; every address carries its language prefix (`/tr`, `/en`). The root address redirects by the browser language and falls back to Turkish; an unknown language returns 404.
- A localized document title on every page.
- Tailwind CSS 4 with a single source for design tokens (`globals.css`).
- The live site sends `noindex, nofollow` until 1.0.0; one environment variable turns indexing on.

# Database
- PostgreSQL 18 and Prisma 7.10; environment variables are validated with zod, and errors never echo the value.
- Local PostgreSQL in Docker with `pnpm db:up` (bound to 127.0.0.1, data volume kept).
- Separate Neon databases for production and preview, both in Frankfurt; the production database can only be connected to the production environment.
- Integration tests run against a real PostgreSQL with a clean test database on every run.

# Quality gates
- 13 required checks on every pull request; a pull request cannot merge while one is red.
- Code: type checking, formatting, ESLint, 7 project Semgrep rules (raw SQL, `dangerouslySetInnerHTML`, `eval`, `process.env` outside the env module, hard-coded secrets, `<script>`, `100vh`), dead code and unused dependency scan.
- Dependencies: high and critical advisories fail the build; production dependencies with licenses incompatible with MIT fail the build.
- Tests: unit and integration; 80% line coverage floor for `src/server` and `src/lib` (currently 100%).
- Security: CodeQL for JavaScript/TypeScript and the workflows; secret scanning with gitleaks.
- Page audit (`site-audit`): horizontal overflow on 10 device views and a 320–2560 px sweep, axe (WCAG 2.2 AA), console and CSP errors in real Chrome; Lighthouse on mobile and desktop (gate 90, expected 95+).
- Placeholder page measurements: performance, accessibility and best practices 100; SEO 90 (description and hreflang arrive in phase 6); 134 KB of JavaScript, 139 KB in total.

# Releases and deployment
- Semantic Versioning: fixes bump PATCH, features bump MINOR, breaking changes bump MAJOR; 1.0.0 is the launch phase.
- Only version tags reach production; merging into `main` publishes nothing by itself.
- Every release is rehearsed once in the preview environment; Vercel builds from the GitHub commit and applies migrations during the build.
- Functions run in Frankfurt (`fra1`), next to the database.

# Project infrastructure
- English Conventional Commits, signed commits, a journal line and a plan tick for every commit, enforced by checks and git hooks.
- Guides for the git workflow and the development environment; CONTRIBUTING and SECURITY.
- 11 architecture decision records (ADR 0001–0011).
