# Security review, November 2026

## Scope

The review covered authorization, uploads, output, public forms, redirects and input, sessions and cookies, visit statistics, and the seed and reset command.

## Method

Code review at v0.8.2. The behaviour of the libraries was read at the pinned versions.

## Result

No write is reachable when signed out or with the demo account. The review found no XSS, open redirect, SQL injection or upload path bypass. Ten smaller items were fixed.

## Fixed items

| Id | Severity | Finding | Fix |
| --- | --- | --- | --- |
| S-01 | Low | A stolen session could start an email change without the password. | The email form asks for the current password. Wrong tries are limited to 5 per 15 minutes per account. |
| S-02 | Low | Anyone could use up the site-wide daily contact ceiling on the demo. | The demo contact form skips the rate limits. |
| S-03 | Low | The public demo sign-in could grow the session table without limit. | Demo sessions last 1 hour, and every successful sign-in deletes expired sessions. |
| S-04 | Hardening | `.env.example` placeholder values were accepted in deployment. | On Vercel, `BETTER_AUTH_SECRET` and `ADMIN_PASSWORD` values that start with the placeholder are refused. |
| S-05 | Hardening | A stale 5 MB Server Action body limit. | The limit is removed and the default applies. |
| S-06 | Hardening | An unvalidated message id in a Prisma `where`. | The id goes through the id schema before the query. |
| S-07 | Hardening | Reset tokens were stored in plain text. | Reset tokens are stored hashed. |
| S-08 | Hardening | A failed session revocation after a password change showed a generic error. | The screen says that other devices may stay signed in. |
| S-09 | Hardening | 404 responses for paths with a dot lacked frame protection, and `X-Powered-By` was sent. | `X-Frame-Options: DENY` on all paths, and no `X-Powered-By`. |
| S-10 | Hardening | Geolocation headers were trusted on every host. | The headers are read only on Vercel. |

## Accepted

- There is no per-account sign-in limit. A public demo account could be locked out by anyone. The 12-character minimum and the per-address limits remain.
- Outside demo mode, the contact form keeps its site-wide daily ceiling. It protects the inbox, and a determined sender can use it up.
- `minimatch` 3.1.5 stays under the lint plugins of `eslint-config-next`. Their latest releases require it, and it runs only during linting.
- The seeded privacy text names sign-in attempts and sessions, but not reset requests, in the rate limit table.
